## 現在地
デスクトップを表示する PC 本体を、モニター一体型のベージュ機・キーボード・マウス・夜の机として `js/pc3d.js`（WebGL2 レイマーチング、外部ライブラリなし）で描いている。
本物の DOM スクリーンは CSS の `matrix3d` でブラウン管のガラスに貼り、着席時は整数 `translate` に戻すので既存アプリの操作はそのまま動く。
起動は部屋の引きの画→ブラウン管点灯→着席のイントロで、部屋をドラッグすると見回せる。
ヘッドレス Chrome のスクリーンショットでホーム・引き・側面・イントロ途中・WebGL 無効時のフォールバックを確認済み。実機ブラウザでの手動確認はまだ。
変更は未コミット（2026年9月30日時点、main 上の作業ツリー）。

## 経緯
### 2026-09-30
#### 3D の PC 本体を新規実装
- 要望: デスクトップを表示している PC 本体を3Dにしたい。古いモニター一体型、キーボードとマウスも置く、雰囲気重視、ブラウン管の質感。
- 途中で「three.js を使わないのか」と聞かれ、README の「外部ライブラリゼロ」「index.html を開くだけで動く」方針と、距離関数のレイマーチングの方が丸い樹脂筐体・柔らかい影を少ないコードで出せることを理由に自前 WebGL で続行した。three.js にするなら切り替えると伝えてある。
- 構成
  - `js/pc3d.js`: シーンのシェーダ（部屋・PC・キーボード・マウス・マグ・フロッピー・ランプ・窓とブラインド・ポスター）、合成とブルーム、カメラ、DOM の射影、埃と湯気の 2D オーバーレイ、入力。
  - `index.html`: `#pc3d-canvas`・`#pc3d-dust`・`#pc3d-hint` と、`#screen` 内に `#crt-fx`（ガラスの減光・映り込み・アパーチャーグリル・リフレッシュの帯）と `#crt-power`（点灯の輝線）を追加。`pc3d.js` は `boot.js` より前に読む。
  - `js/boot.js`: `window._pc3dPowerOn(cb)` があればブラウン管の点灯を待ってから BIOS 表示を始める。
  - `css/style.css`: `body.pc3d` 配下だけに効くルールを末尾に追加。WebGL2 が無い・シェーダが通らない・9秒以内にコンパイルが終わらないときは `pc3d` クラスを外し、従来の平面モニターに戻す。
- 描画の設計
  - 視点が動いている間は CSS px の0.33〜0.75倍の低解像度で1サンプル、止まったら全解像度で8（DPR2）〜14サンプルを帯に分けて積み上げ、終わったら重い描画を止める。M1 Pro の計測では高品質1サンプルが1440×900で18ms、2880×1800で62ms、移動中の低解像度が3〜5ms。
  - ブラウン管から部屋へ届く光（多角形光源の形状係数＋光沢面への映り込み）は別の描画先 `oScr` に分け、合成時に「画面の平均色」を掛ける。画面の平均色は壁紙キャンバスの平均と開いているウィンドウの面積から1秒ごとに見積もるので、テーマ切替でも再描画せず部屋の色が変わる。
  - 着席ビューはカメラの像面をブラウン管の面と平行にし（ピッチ0）、レンズシフトで下の机を入れる。これでスクリーンが常に440×330の長方形に投影され、DOM を整数座標へ置ける。構図は画面の高さに合わせて目の高さ（0.12〜0.24m）を選ぶ。
- 学習ポイント（ハマった点）
  - ヘッドレス Chrome の `--screenshot` は撮影時だけ表示領域を `--window-size` まで広げ、`100vh` のキャンバスだけが引き伸ばされる（`innerHeight` は813、画像は900）。3D と DOM がずれたように見えた。キャンバスの CSS サイズを px で固定し、`--window-size` を87px 高くして900px の表示領域で撮るようにした。
  - ブラインドの距離関数で、羽根の外側（窓の上下）でも「隣の羽根までの距離」の下限式が負になり、窓から遠い机の上に偽の面が出た。ブラインド全体の外接箱で先に弾くようにした。
  - IQ の「改良版」ソフトシャドウ（`y=h*h/(2*ph)`）は前ステップの h だけ進む前提で、最小ステップ0.0015で底上げすると `y>h` になって半影が0（真っ暗）になる。右ベゼルに鋸歯状の影が出ていた原因。古典式 `res=min(res,k*h/t)` に戻した。
    ```glsl
    // before: float y=h*h/(2.0*ph); float d=sqrt(max(h*h-y*y,0.0)); res=min(res,k*d/max(0.0001,t-y));
    res=min(res,k*h/t); t+=clamp(h,0.0015,0.06);
    ```
  - 同じ場所では、月へ向かう影のレイがくぼみ奥の CRT ガラスすれすれを通って半影で暗くなってもいた。ガラスは影を落とさないので、影のレイでは `gShadow` フラグで除外した。
  - キーの距離関数は「隣のキーまでの下限」で割っているが、キー領域の外（キーボード前面）でもその下限が効いてレイが1.1mm刻みでしか進めず、ステップ切れの抜けが目盛り状に出た。キー領域の矩形までの距離と max を取って外では効かないようにした。
  - ランプの霧を20点のサンプリングで積分すると電球付近で年輪状の縞が出たので、点光源の散乱は `atan` の解析解にし、スポットの減衰は最接近点の1点で取った。
  - 原因の切り分けには、法線・遮蔽物までの距離・半影の最小値とその地点の材質を色で出すデバッグ表示が効いた（調査後に削除済み）。
